## Design / administrator setup

Earlier HTTPS/proxy requirement was our safety design, NOT a ComfyUI constraint. Explicit `COMFYCHAIR_AUTH_MODE=lan` needs ONE dedicated cryptographically random secret >=32 characters in `COMFYCHAIR_DELETE_SECRET`, no proxy secret, trusted peer or principal. No secret generated by this task. Default mode `proxy` remains supported; unset/short key, invalid mode, incompatible queue/corrupt journal fail closed. Journal defaults to persistent trusted plugin `missing.json`, optional absolute private persistent override; KEEP journal across plugin upgrades, ZIP contains no state.

App Settings → Server gallery → Deletion key: SAME key, enable Trusted LAN deletion (allow HTTP), read warning and Store securely to consent. Key and toggle encrypted/failclosed, scoped to server ID AND exact origin (hostname/port/protocol); no old beta5 server-ID-only credential migration, re-enter key. No proxy internals in UI. Existing login auth unchanged. No key or no transport consent does not break normal gallery browsing. Capability public protocol/auth-mode discovery contains no user descriptors. `/missing` now same key/auth gate as prepare/delete: no-key clients cannot filter private tombstones and may see stale asset references. App uses saved authorized key for missing metadata.

HTTP is plaintext, not encrypted: key and operation tokens can be intercepted/replayed; shared key grants admin deletion, no per-user LAN roles. Trusted private LAN ONLY, never Internet/untrusted Wi-Fi. HTTPS still available; unchanged self-signed policy. UI switch+save consent is explicit, no arbitrary remote HTTP key send; redirects and write retries disabled. Owner rechecked after credential IO and before prepare/delete; old owner results cannot mutate new session UI. Regular cache/gallery/directInput features retained.

Unchanged safety: constant-time bytes key check (including malformed Unicode deny), queue real mutex and any-job guard, Linux dirfd every-component O_NOFOLLOW, no traversal/symlinks/hardlinks/recursion, batch50/32KiB streamed body, random snapshot-bound operation tokens TTL120s/idempotent10min/max256, persistent pre-unlink tombstone intent/max5000. External writers and final POSIX stat→unlink replacement races still require admin exclusion. Tombstones may hide surviving/recreated paths; other UI/history/assets not synchronized. Existing list/thumbnail invalidation and immutable upload/selected bitmap/snapshot preservation retained.
