# Configurable persistent server-image cache — beta.3 / code57

## Accepted behavior
- Settings has an in-place card: automatic switch, maximum MB (1–1024) and days (1–365), default ON/64/7. Numbers validated before save; committed in AppSettings preferences, applied to all live clients sharing one no-backup cache. MB = 1024² bytes.
- OR policy: expired creation age > configured days is removed regardless of size; if bytes exceed maximum, remove oldest-created entries until under limit. Stable HMAC filename tie-break. Reads never renew creation age. Existing beta2 entry format retained.
- Automatic OFF skips user age/size cleanup. Separate hard 1024 MiB/8192 entry safety ceiling remains (also disclosed in EN/ZH UI). Individual entry remains at most4 MiB. Cleanup opportunistic on get/put/apply, not a background service. Freshness TTLs independent: list/thumb24h, upload7d; stale miss does not delete merely for TTL with policy-managed cache. Corrupt/future entries recover as misses.
- Separate manual clear works autoOFF, inline second click within3seconds; disabled/progress/result/error feedback. Only .entry and pending-*.tmp files in noBackupFilesDir/server-image-cache-v1 are cleared, all server/auth namespaces, HMAC namespace.key retained. Never calls old broad clearCache (which clears workflows/media). Selected sources/materials/workflows/comparison snapshots and server files untouched.
- Shared disk lock serializes reader/publication/deletion; generation captured before network work rejects pre-clear writes for thumbnails/lists/uploads. Active picker closes/clears list and preview memory; bitmap objects are not recycled. Current client upload memory cleared; other client memory generations miss on next access. In-progress uploads can complete safely without publishing into cleared cache. Direct Input provenance/client epoch is not invalidated by cache clear; existing authenticated HEAD behavior unchanged.
- Current cache size/count shown from IO checksum-valid entry scan. Count excludes namespace key, pending/temp, unrelated files and corrupt entries. Size sums exact valid entry lengths including44-byte headers, excludes key/temp/corrupt. Uses Android Formatter plus raw byte count. Freshness-expired but structurally valid retained files still count. Loads when card enters composition; successful save/clear refreshes; explicit refresh supports auto-cleanup/other changes. Loading/error text and disabled refresh; does not read on UI thread. Snapshot statistics, not continuously polled.
